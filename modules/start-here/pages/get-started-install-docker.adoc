== Before You Begin

Before you begin, make sure that:

* Docker runs on your machine.
See the https://docs.docker.com/get-docker/[Docker installation guide, window=_blank].
* You have read the requirements in {get-started-prepare--xref}.
You complete the Couchbase Server configuration steps from that page after you start the {cbs} container.


== Deploy Couchbase Server

=== Create a Docker Network

Create a Docker bridge network so that the {cbs-te} and {sgw-te} containers can communicate.

[{snippet-header}]
----
docker network create --driver bridge couchbase
----

=== Run Couchbase Server

Run {cbs} in a Docker container on the `couchbase` network.

[{snippet-header}]
----
docker run -d --name cb-server \
  --network couchbase \
  -p 8091-8097:8091-8097 \
  -p 11210-11211:11210-11211 \
  couchbase/server:{cbs-docker-tag}
----

TIP: The command pins the image to a specific version.
To use a different version, first check that {sgw} supports it in the xref:get-started-prepare.adoc#lbl-req-compat[Compatibility Requirements].

=== Configure Couchbase Server

When {cbs} is running, open the Admin Console at `+http://localhost:8091+` and complete these steps from {get-started-prepare--xref}:

. Create a cluster.
. Create a bucket.
. Create an RBAC user with the _Sync Gateway_ role (`mobile_sync_gateway`) for the bucket.

NOTE: Record the bucket name and the RBAC user credentials.
You need them in the next step.


== Deploy Sync Gateway

=== Create a Configuration File

Create a configuration file named `sync-gateway-config.json` on your local machine.

Replace `<rbac-username>` and `<rbac-password>` with the credentials of the RBAC user that you created in {cbs}.

[#sample-cfg]
.Sync Gateway Bootstrap Config for Docker
====

[source, json]
----
{
  "bootstrap": {
    "server": "couchbase://cb-server", // <.>
    "username": "<rbac-username>", // <.>
    "password": "<rbac-password>",
    "use_tls_server": false // <.>
  },
  "api": {
    "admin_interface": ":4985" // <.>
  },
  "logging": {
    "console": {
      "enabled": true,
      "log_level": "info",
      "log_keys": ["*"]
    }
  }
}
----

<.> Use the {cbs} container name `cb-server` as the hostname.
Docker resolves this name within the `couchbase` network.

<.> Use the credentials of the RBAC user with the _Sync Gateway_ role (`mobile_sync_gateway`).

<.> This configuration disables TLS for local development.
For production deployments, enable TLS and use `couchbases://cb-server` instead.

<.> {sgw} binds the Admin REST API to `127.0.0.1` by default, which makes it unreachable from outside the container.
This setting binds the Admin REST API to all interfaces inside the container, so that the host can reach it through the port mapping in the next step.

====

=== Run Sync Gateway

Run {sgw} in a Docker container and mount the configuration file that you created.

Replace `/path/to/sync-gateway-config.json` with the absolute path to the file on your local machine.

[{snippet-header}]
----
docker run -d --name sync-gateway \
  --network couchbase \
  -p 4984:4984 \
  -p 127.0.0.1:4985:4985 \
  -v /path/to/sync-gateway-config.json:/etc/sync_gateway/config.json \
  couchbase/sync-gateway:{version-full}-enterprise \
  /etc/sync_gateway/config.json
----

WARNING: Port 4985 serves the {sgw} Admin REST API.
The `127.0.0.1:4985:4985` mapping publishes the Admin port to your local machine only.
Do not expose port 4985 to external traffic in production environments.

NOTE: The Admin REST API requires authentication by default.
To create a database, which the next steps require, use the credentials of a user with the _Full Admin_ role, such as the administrator that you created during cluster setup.
The _Sync Gateway_ role (`mobile_sync_gateway`) cannot create a database.


== Verify the Connection

. Open the {sgw} public port in your browser:
+
[{snippet-header}]
----
http://localhost:4984
----

. Confirm that you receive a response similar to this:
+
[{snippet-header}]
----
{"couchdb":"Welcome","vendor":{"name":"Couchbase Sync Gateway","version":"{version}"},"version":"Couchbase {sgw}/{version-full} EE"}
----
+
If you have issues, check the {xref-sgw-bmk-logging-console} for more information.


== Manage Your Containers

=== Stop Containers

[{snippet-header}]
----
docker stop sync-gateway
docker stop cb-server
----

=== Start Containers

Start {cbs} before {sgw}.

[{snippet-header}]
----
docker start cb-server
docker start sync-gateway
----

NOTE: If {cbs} stops for an extended period, {sgw} loses the connection.
Restart {sgw} after you restart {cbs}.

=== Update the Sync Gateway Configuration

To update the {sgw} configuration, stop and remove the container, then run it again with the updated configuration file.

[{snippet-header}]
----
docker stop sync-gateway
docker rm sync-gateway
----

Then repeat <<run-sync-gateway>>.
