== What You Need

To install {sgw}, you need to:

* Confirm that your setup meets the <<lbl-req-minim>> and <<lbl-req-compat>> for running {sgw}.
* Have access to a working Couchbase Server deployment configured for {sgw}, or know how to {server-install-get-started--xref}.
* <<configure-server>>, including an appropriate set of RBAC users for {sgw} and its REST APIs.
* Have the appropriate network credentials and <<lbl-set-netw-access, Network Access>>.

When you have completed these tasks, go to {get-started-install--xref} {sgw-t}.

[#lbl-req-minim, reftext=Minimum Requirements]
== Couchbase Server Requirements

{sgw} requires an operational Couchbase Server installation.
Verify that your Couchbase Server and {sgw} versions are compatible.
See <<lbl-req-compat>>.

TIP: You can get Couchbase Server from the {url-downloads}[Downloads, window=_blank] page.

You then configure Couchbase Server by adding a bucket and an RBAC user for {sgw}.
See <<configure-server>>.

== Cluster Configuration for Sync Gateway

To create a new cluster on a fresh Couchbase Server installation:

. Open the Admin Console at `+http://localhost:8091+`.
. Select btn:[Setup New Cluster].
. On the `New Cluster` screen, enter a *Cluster Name*, an administrator *Username*, and a *Password*, then confirm the password.
. Select btn:[Next: Accept Terms].
. On the `Terms and Conditions` screen, accept the terms and conditions.
. Select btn:[Configure Disk, Memory, Services].
. Select the `Data`, `Query`, and `Index` services.
. Select btn:[Save {amp} Finish].

== Configure Server for Sync Gateway


=== Step {counter: step}: Create a Bucket

Create a bucket to test your {sgw} deployment later in the Getting Started section.

. Log in to the Couchbase Server Admin Console:
[upperroman]
.. Go to `+http://localhost:8091+`.
.. Enter your administrator credentials.

. In the Admin Console toolbar:
[upperroman]
.. Select the *Buckets* tab.
.. Select btn:[Add Bucket].
.. In the pop-up window, enter *get-started-bucket* in the *Name* field.
.. Select btn:[Add Bucket].
You can leave the other options at their defaults.

[#create-rbac-user]
=== Step {counter: step}: Create RBAC Users

// tag::create-rbac-user[]

{sgw} uses RBAC user credentials to authenticate and authorize access to Couchbase Server buckets and to its own Admin and Metrics REST APIs.
Create at least one user for {sgw} to access Couchbase Server.
If you plan to use the Admin or Metrics REST APIs, also create one user for each API:

* Couchbase Server access +
Add an RBAC user that {sgw} uses to authenticate and authorize access to Couchbase Server.
Assign the _Sync Gateway_ role (`mobile_sync_gateway`) to this user, for each bucket that {sgw} uses.
* Admin REST API +
Add an RBAC user that administrators use to authenticate and authorize access to the {sgw} Admin REST API.
Assign the _Full Admin_ role to this user.
* Metrics REST API +
Add an RBAC user that DevOps teams use to authenticate and authorize access to the {sgw} Metrics REST API.
Assign the _Read-Only Admin_ or _Application Access_ role to this user.

Enterprise Edition users can apply finer-grained control by assigning the additional {sgw} roles that match the capabilities each user needs.
For the full list of {sgw} roles, see {xref--pfx-svr}learn:security/roles.adoc#sync-gateway[Couchbase Server Roles].

NOTE: For more information about creating Couchbase Server users, see {server-manage-security-users-and-roles--xref}.

// end::create-rbac-user[]

To create the user that {sgw} uses to access Couchbase Server:

. In the Couchbase Server Admin Console, select the *Security* tab.
. Select btn:[Add User].
. In the *Add New User* dialog, enter a *Username* and a *Password*, then verify the password.
. In the *Roles* section, expand the *Mobile* category.
. Select *Sync Gateway*, then select *get-started-bucket*.
. Select btn:[Save].

Record the username and password.
You add them to the {sgw} bootstrap configuration when you install {sgw}.
