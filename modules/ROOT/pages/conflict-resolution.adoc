== Overview

Starting with Sync Gateway 4.x, the default conflict resolution strategy has changed from *Most Write Wins* (MWW) to *Last Write Wins* (LWW). This fundamental change aligns with the shift from revision trees to version vectors and enables better consistency across distributed deployments.

Conflicts are automatically resolved footnote:[Since Couchbase Lite 2.0] using deterministic algorithms that verify consistency across all participating nodes.

== Conflict Resolution Strategies

=== Last Write Wins (Default in 4.x+)

Last Write Wins uses hybrid logical clock timestamp comparison to resolve conflicts deterministically.
The document with the latest timestamp wins the conflict, with timestamps generated using version vectors and Hybrid Logical Vectors (HLV) for accurate ordering.

This strategy provides:

* Deterministic conflict resolution across all clusters
* Consistency with XDCR timestamp-based conflict resolution
* Better support for active-active deployments
* Alignment with modern distributed systems practices

=== Most Write Wins (Versions < 4.x)

Sync Gateway uses Most Write Wins conflict resolution in the following scenarios:

* Sync Gateway 4.x replicating with Couchbase Lite < 4.x clients
* Sync Gateway 4.x replicating with Sync Gateway < 4.x instances
* Cross-version compatibility scenarios

In these cases, the document with the most revisions wins the conflict, maintaining backward compatibility.

NOTE: For Sync Gateway versions less than 4.x, Most Write Wins is the default behavior.
See xref:upgrading.adoc[Upgrading Sync Gateway] for upgrade instructions.

== XDCR Integration

For active-active deployments using XDCR with Sync Gateway 4.x, configure your Couchbase Server buckets to use *Timestamp-based* conflict resolution to match Sync Gateway's Last Write Wins behavior.

This ensures consistent conflict resolution across:
* Sync Gateway ↔ Couchbase Lite replication
* XDCR bucket-to-bucket replication
* Mixed mobile and server-side application scenarios

See xref:server-compatibility:server-compatibility-xdcr-mobile.adoc[BI-directional XDCR with Mobile Clusters] for detailed configuration guidance.
